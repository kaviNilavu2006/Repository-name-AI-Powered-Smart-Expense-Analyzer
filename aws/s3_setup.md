# Amazon S3 Setup Guide

This guide explains how to create and configure the S3 bucket used to store uploaded receipt images.

## 1. Create the Bucket

1. Sign in to the [AWS Console](https://console.aws.amazon.com/).
2. Search for **S3** and open the service.
3. Click **Create bucket**.
4. **Bucket name:** choose a globally unique name, e.g. `smart-expense-analyzer-receipts-yourname`.
5. **AWS Region:** select **Asia Pacific (Mumbai) ap-south-1** (to match the rest of the project).
6. **Block Public Access settings:** keep **all four boxes checked** (Block all public access). Receipts are private and should only be accessible via presigned URLs generated by the backend.
7. Leave **Bucket Versioning** disabled (optional for a student project).
8. Leave **Default encryption** at **Amazon S3-managed keys (SSE-S3)**.
9. Click **Create bucket**.

## 2. Configure CORS (Required for Direct Browser Uploads, Optional Here)

This project uploads receipts through the Flask backend (not directly from the browser), so CORS configuration on the bucket itself is **not required**. Skip this step unless you extend the project to upload directly from JavaScript.

## 3. Required IAM Permissions

The Flask application needs an IAM role/user with these S3 permissions on your bucket:

- `s3:PutObject`
- `s3:GetObject`
- `s3:DeleteObject`
- `s3:HeadBucket` (used to verify connectivity on startup)

See `aws/iam_setup.md` for the exact policy JSON.

## 4. Upload a Test Receipt (Manual Verification)

1. Open your bucket in the S3 console.
2. Click **Upload**, then **Add files**.
3. Select any JPG or PNG image and click **Upload**.
4. Confirm the object appears in the bucket listing.
5. Delete the test file afterward (optional).

## 5. Update Your Environment Variables

In your `.env` file (copied from `.env.example`):

```
S3_BUCKET_NAME=smart-expense-analyzer-receipts-yourname
AWS_REGION=ap-south-1
```

## How Receipts Are Stored

When a user uploads a receipt:

1. The Flask backend validates the file type (JPG, JPEG, PNG, PDF only) and size (max 5 MB).
2. A unique object key is generated: `<user_id>/receipt_<unique_id>.<extension>`.
3. The file is uploaded to S3 via `boto3`.
4. A **presigned URL** (temporary, expiring link) is generated so the receipt can be viewed securely without making the bucket public.
5. The object key and URL are stored alongside the expense record in DynamoDB.

## Local Development Without S3

If AWS credentials are not configured, `services/s3_service.py` automatically falls back to storing receipts on the local filesystem under `/uploads`, so the app remains fully functional for local demos without any AWS account.

## Why S3?

- **Durable, low-cost object storage** purpose-built for files like receipt images.
- **Presigned URLs** allow secure, temporary access without making files public.
- **Decouples file storage from the database** — DynamoDB only stores lightweight metadata (the S3 key/URL), keeping the database fast and cheap.
